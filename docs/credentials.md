# 方舟图片、视频凭据

ChatGPT 订阅登录用于 GPT 对话与策划，方舟 API Key 用于火山图片和视频生成。两者分别认证；重新启动 Nolan 不应要求反复配置已经保存的方舟 Key。

## 在本机保存一次

在你自己的 Mac 终端执行：

```bash
nolan ark-login --resume -C "/Users/jts2025/Desktop/御剑飞行"
```

在隐藏输入框粘贴方舟 API Key 后回车。Nolan 把它保存到本机 macOS 钥匙串，然后恢复 GPT 对话并沿用工作目录。不要把 Key 发到聊天，也不要写进命令参数、项目 JSON、小说、提示词或仓库。此命令仅保存登录，不生成图片或视频，不修改预算与审批进度。

如果当前终端已设置 `ARK_API_KEY`，明确运行 `ark-login` 会直接把该值保存到钥匙串，无需再次输入。此前只在某个进程环境中设置、没有持久保存的凭据，进程退出后可能无法恢复；这种情况需要本人在终端重新保存一次。

只保存、不启动另一段对话：

```bash
nolan ark-login --no-launch
```

保存后，已运行的旧版 Nolan 或审片室服务需退出并重新启动才能加载新代码和凭据。以后正常运行 `nolan --resume` 或指定工作目录即可，升级不会删除钥匙串记录。

## 读取顺序与更新

1. 当前进程中非空的 `ARK_API_KEY` 环境变量。
2. 当前 Mac 用户的 Nolan 钥匙串记录。

项目文件不会保存 Key，也不会覆盖这两处凭据。`nolan doctor` 只显示配置来源或故障原因，不显示 Key 内容。

更换 Key 时，再运行一次 `nolan ark-login`，隐藏输入新值即可更新同一条钥匙串记录。如果当前终端仍设置着旧的 `ARK_API_KEY`，它会优先使用旧值；请先在本机终端执行 `unset ARK_API_KEY`，再运行 `ark-login` 输入新值。无需更改项目、重新生成资产或重做审批。

## 无法读取时

- 钥匙串锁定或系统拒绝访问时，Nolan 会明确提示解锁或访问问题，不把它当成“尚未配置”，也不自动改存明文文件。按 macOS 的本机提示允许访问后重试。
- 自动化或没有安全隐藏输入能力的终端不会从聊天或标准输入收集 Key。请本人在交互终端运行 `nolan ark-login`。
- 更换 Mac、换用其他 macOS 用户或撤销 Key 后，需要在对应机器或账户重新保存有效凭据。
- 能读取 Key 不等于模型权限或账户余额正常。供应商拒绝时按具体错误处理，不要反复保存或自动重复提交素材。

本地音乐文件夹不需要方舟 Key 或 AK/SK。另行开通的火山纯音乐服务使用其自己的 AK/SK，不能由方舟 Key 替代。
