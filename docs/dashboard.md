# 本地审片室

Norlan 的终端对话负责日常控制；审片室用于集中查看分集策划、资产候选、需要人工复核的镜头以及每集成片。启动方式以 `norlan studio --help` 为准，默认地址是 `http://127.0.0.1:8765`。

## 审批顺序

1. **分集策划**：核对风格、画幅、各集剧情以及镜头时长。批准后开始生成资产；修改意见会交回策划流程。
2. **资产**：逐一确认人物、场景、道具和声音候选。每次按钮只批准当前资产，未批准的其他资产继续阻止视频生产。声音候选支持音频或视频试听。
3. **镜头复核**：自动检查不能确定时，展示当前镜头与上一镜，保留检查记录。需要人工看完接续、听完声音并勾选确认，才能通过该镜。抽帧分析本身不等于完整视频或音频审看。
4. **逐集成片**：播放本集，核对画面、对白、字幕与音乐。可填写具体时间点和修改要求，并选择影响镜头；留空将返工本集全部镜头。批准本集后才继续下一集。

本集已有实际对齐字幕时，使用单独的“修改字幕”按钮更正文字，保留原视频镜头和字幕时间，再重新合成与审片。成片卡片会显示独立配乐、字幕烧录与自动检查的限制，并可下载当前字幕文件。

“确认并继续”“批准策划并生成资产”和“通过本集并继续下一集”会保存这一次审批，再自动启动制作流程。流程在下一个审批节点、预算限制或错误处停下。每次审批都带具体版本；旧页面不能批准已更新的素材。

模拟项目始终显示黄色 DEMO 说明，其画面、音频与费用都用于验证流程，不作为真实生成结果。预算显示已用、已预留和待核实金额；待核实不视为可用余额。

“暂停新任务”阻止后续提交。已经送到供应商的任务可能继续执行和计费。关闭正在执行任务的审片室也会先设置暂停；应重新启动 Norlan 查询持久化任务状态，不要重复提交未知结果的任务。

## 本地接口

`norlan.dashboard.serve(project_dir, port=8765, open_browser=True)` 启动服务。测试或嵌入可使用 `make_server(project_dir, port=0)` 创建未启动的服务器。

| 地址 | 用途 |
| --- | --- |
| `GET /` | 内置页面，附带本次服务器会话令牌 |
| `GET /api/state` | 经过字段筛选的项目状态 |
| `GET /media/<relative-path>` | 只读取项目状态中引用的媒体文件，支持视频 Range 与 HEAD |
| `POST /api/action` | `approve`、`reject`、`captions`、`run`、`pause` |

POST 使用 `application/json`，携带 `X-Norlan-Token`；审批载荷包含 `kind`（`plan`、`asset`、`shot` 或 `episode`）、`id`、`version`。拒绝另外包含 `feedback`，分集可附 `shot_ids`。这些接口只用于本地审片室，不是对公网提供的服务。

## 访问边界

服务仅绑定 `127.0.0.1`，校验准确的 Host 与 Origin。每次启动使用随机 CSRF 令牌，所有变更均走 POST，拒绝超过 32 KiB 的请求；页面使用内容安全策略，无外部脚本、字体或跟踪器。

媒体路由只允许当前项目状态明确引用的图片、视频、音频或字幕，拒绝路径穿越、符号链接与任意文件读取；SRT/VTT 仅作为附件下载。配置、小说原文、任务响应和凭据不通过状态接口返回。异常响应不包含原始供应商响应或堆栈；项目的提示性错误会再次隐藏常见凭据格式。

这是本机工具，不应将端口反向代理或转发到公共网络。它没有多用户身份系统，也不替代操作系统的账户隔离。
