# 本地工作目录与原生工具

Nolan 的终端入口运行本机已安装的原生 Codex CLI，再加载 Nolan 的制作工具。0.7.8 起，保留 Codex CLI 的本地文件、搜索、编辑和命令执行能力，可以先浏览文件夹找剧本，再调用制作工具；不再要求你手工提供每个 TXT/MD 的准确文件名。

## 选择工作目录

```bash
nolan -C "/Users/jts2025/Desktop/御剑飞行"
nolan chat -C "/Users/jts2025/Desktop/御剑飞行"
nolan --resume -C "/Users/jts2025/Desktop/御剑飞行"
nolan chat --resume -C "/Users/jts2025/Desktop/御剑飞行"
```

`-C` 与 `--cd` 等价，可放在 `chat` 前后。相对路径按运行命令时的目录解释；目录必须存在。重复指定不同的目录会报错，不悄悄采用最后一个。`--cd` 仅用于无子命令的原生对话和 `chat`，不会改变 `run`、`studio`、`status`、`configure` 等制作命令的参数含义。

也可先在终端 `cd` 到业务文件夹，再运行 `nolan`；从家目录或 Nolan 内部运行目录启动时，不会自动把整个家目录设成可写工作区。恢复会话保留最近使用的工作目录；用 `--resume -C 新目录` 可在恢复原对话时明确切换目录，不会因为目录改变而只找新目录里的旧对话。

启动后可以直接说：“浏览这个文件夹，找出《御剑飞行》的剧本，先告诉我找到了哪些文件。”“在当前目录新建一个独立制作子目录，输出素材也放在那里。”模型会先检查文件和已有项目；多个剧本无法明确区分时，再让你选择。

`nolan chat ./my-drama` 中的位置参数仍指已有 Nolan 制作项目，必须具有真实 `project.json`。普通素材或剧本文件夹请使用 `-C`，不要把它当作项目传入。工作目录和已有项目可以同时指定，例如：

```bash
nolan chat ./my-drama -C ./story-materials
```

在指定目录开始新制作时，使用其内独立、为空的子目录，避免将项目文件混进小说或覆盖已有素材。旧项目保留原路径、资产、费用记录、人工审批和生成进度；选择工作目录不会移动、重建或自动继续旧项目。

## 文件和命令权限

原生会话采用 `workspace-write` 沙箱和 `on-request` 审批策略。模型可在工作目录内完成常规读取、编辑和命令执行，需要扩大权限的操作交由 Codex CLI 的终端审批。操作系统的隐私保护、只读目录和文件权限仍然有效；macOS 拒绝访问桌面或文稿时，应按系统提示为启动 Nolan 的终端应用授权。目录路径并不能绕过操作系统权限。

文件工具并不授予制作审批权限。模型仍不得直接编辑 `project.json` 来伪造批准、清除未知调用或触发重复生成。资产、完整视频提示词、每版视频和整集成片的人工审批继续使用 Nolan 审片室及既有工具。

## 能力范围

这是对本机 Codex CLI 原生能力的接通。它不等于完整嵌入 Codex 桌面应用：桌面浏览器控制、桌面插件、其他应用连接器和本聊天的全部工具不会因此自动出现在 Nolan 中。可用工具还取决于当前安装的 Codex CLI 版本及 Nolan 的独立配置。Nolan 保留订阅/API 的独立登录与会话，不会复制桌面应用的密钥或连接状态。

配置和命令行为可参阅 [Codex 官方基础配置](https://learn.chatgpt.com/docs/config-file/config-basic)与[官方 CLI 命令说明](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。
