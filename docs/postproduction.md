# 每集后期

0.6.0 的真实项目默认开启每集“本集后期”；旧项目需显式设置 `settings.postproduction.enabled=true`，原有视频、逐段审批、资产和费用记录保持原样。新项目默认约一分钟一集；已有130秒第一集不改时长。

流程是：逐段批准 → 原声粗剪 → 本地识别 → GPT订阅校对 → 音乐首次试听审批 → 本地音频分析与 GPT 选段编排 → 响度统一、混音与本地检查 → 带字幕配乐的整集人工审批。后续集只复用已批准音乐，缺少合适音乐时可以随时导入新的候选。

网页“本集后期”位于累计拼接和片段区之后。后期完成时，区域顶部直接播放带字幕和配乐的最终成片，紧接当前版本的最终审批；字幕、音乐安排和修改意见也在这个区域。原声粗剪继续在前面的累计拼接区查看，后期区域不再重复展示。字幕和音乐意见只重新合成后期，保留已有视频。返修尚未完成时不把旧版冒充本次最终成片；最终通过只针对完成后期的当前版本，审批校验原片、字幕、音乐文件与编排哈希。下一集须等本集最终批准。

## 本地字幕

运行 `bash scripts/install-local-asr.sh`，依赖是 whisper-cpp、FFmpeg 和约466MiB官方 small 多语言模型。字幕使用 `settings.subtitles.mode=local`，GPT连接需在 `nolan setup` 选择ChatGPT订阅。无需另开 OpenAI API。识别和校对按真实音频、模型与任务内容缓存，重启不会重做已有校对。详见[字幕](subtitles.md)。

## 首次音乐

0.6.1 起，新建真实项目默认使用本地曲库。将有适用许可的音乐下载到本地文件夹，在网页填写路径并扫描；片段未完成时也可提前试听确认。后期按剧情从已批准曲目中选择，每次最多给 GPT 12 首的紧凑标签，不把整库、许可全文和扫描历史反复塞入上下文。详情见[本地音乐文件夹](local-music-folder.md)。

每集导出 `*.credits.txt`，列出实际用到的曲目、作者、来源、许可链接、署名文本和剪辑混音说明，不增加正片时长。发布成片时保留相应署名；本地源文件和未选中的曲目不修改、不进入本集署名。

最省配置的方式是在网页导入 WAV、MP3、M4A、OGG 或 FLAC（每首≤30MiB，有合法使用权限）。Nolan复制到项目音乐库，实测时长并记录文件哈希，点击试听后由本人批准；模型不能批准。未批准音乐不进入编排。拒绝候选不会自动再生成。

如需自动生成，在[火山AI音乐控制台](https://console.volcengine.com/ai-music/product)开通“生成纯音乐”的按时长后付费服务，取得AK/SK。回到你自己的终端，退出旧Nolan后运行 `nolan music-login --resume`，按提示隐藏输入AK、SK，再让Nolan打开原项目审片室。凭据只保留在本次进程，退出后下次需重新输入；不写进项目、聊天或配置文件。已通过环境变量提供 `VOLC_ACCESS_KEY_ID` / `VOLC_SECRET_ACCESS_KEY` 时不再询问。

这是独立服务，不能使用方舟API Key，也不复用即梦网页会员。程序不会代替你购买套餐或开通付费服务。当前项目使用后付费 `GenBGMForTime`，预付费套餐不能自动抵扣后付费；参见[官方开通指南](https://docs.volcengine.com/docs/Audiovideounderstandingandprocessing/ConsoleServiceActivationGuide?lang=zh)和[产品计费](https://docs.volcengine.com/docs/Audiovideounderstandingandprocessing/Productbilling?lang=zh)。项目非秘密设置为：

```json
{"music":{"mode":"volc","action":"GenBGMForTime"}}
```

无需配置 `call_cap` 或项目预算。只有点击“生成一首新音乐”才授权一个新候选。先登记调用，再提交、保存供应商任务ID、查询和下载；结果不明不重发。当前音乐API适配器已做模拟协议测试，未用真实账户付费验证。

生成的候选按本集时长选择30–60秒；单次服务上限不限制整集长度。GPT可在130秒时间轴上显式安排多条音乐片段、留白和交叉淡化，每段都校验素材真实范围。不会拉伸音乐、隐式循环或缩短视频。编排只接收当前集的精简剧情/对白窗口、已批准音乐目录和上一集结尾少量cue。

自动编排先分析实际音乐的响度、能量变化与可用段落，再由 GPT 结合剧情选择原曲的截取位置，不只默认取开头。分析缓存绑定原音频哈希，只有紧凑的候选段落摘要进入 GPT 上下文。先统一音源响度再应用编排音量；对白时间窗内有限压低配乐，不再让环境声持续触发整轨压低。原视频若把对白、环境声和已有音乐混成单轨，FFmpeg 仍无法分离它们；建议后续视频提示词只保留对白/环境声，独立背景音乐统一放在后期制作。

混音后本地检查安排了音乐的时段是否过轻、是否压过对白或出现削波，并有限次修正；故意留白不当成漏混。网页展示默认折叠的“配乐检查报告”，可查看分析摘要、响度基准、对白压低上限、修正次数和疑点时段。数字检查不证明听感或剧情适配已经通过，当前版仍须本人完整试听和最终审批。

音乐列表显示每条截取原曲的起止位置；可拖动音量并手动修改其在本集的开始、结束时间。手动保存直接采用你的设置，只重新生成本地试看版，不再调用 GPT、重新分析选段、自动复检或改音量。字幕的手动调整同样直接采用，不再自动校对或对齐。

## 恢复与返修

重启或点继续只恢复已有任务和缓存；不会重新提交视频或音乐。字幕意见只失效字幕校对及最终导出，音乐意见只失效音乐编排及最终导出。旧成片、原音乐、字幕和历史版本保留。每次新导出都重新等待整集审批。

配置缺失、识别/编排失败和待试听确认分别在网页显示；不会用测试音或静音冒充已完成音乐。字幕无法烧录时停止最终放行，保留SRT和视频供检查。

0.7.7 起，字幕文字冲突与时间偏移分别处理。剧本或 GPT 改字未获音轨支持时，只可恢复同时间唯一对应的原识别候选，且须独立声学完整支持、复检不新增其他问题；不改时间、不改数字、不以剧本覆盖真实声音。失败报告、文字恢复依据和原有时间修复次数保留；升级检查器不会重置两次额度。用户手动保存的文字和时间不经过此自动处理。

字幕仍有疑点时，可以烧录“字幕待核验预览”供对照与修改，检查报告保留，最终批准继续被阻止。继续不会重复合成同版预览或重复编配音乐。只有同步检查通过，或用户明确手动保存调整后，才进入相应的整集人工审批。缺少 libass 字幕滤镜或中文字体时，在耗时渲染前停止并明确显示所缺能力，不再先产出无字幕视频。
