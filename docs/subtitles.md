# 根据实际对白制作字幕

## 默认流程：本地识别 + GPT订阅校对

0.6.0 新建真实项目默认启用“本集后期”。本集片段全部人工通过后，本机 whisper.cpp 识别已拼接原声音轨，得到实际文字与时间戳；GPT 通过 Nolan 现有 ChatGPT 订阅连接分批校对专名、错别字和标点。不需要 OpenAI API Key，不调用云端转录，不把本机识别记成供应商实际费用。GPT 订阅额度仍按账户规则消耗。

macOS 执行 `bash scripts/install-local-asr.sh` 安装 whisper-cpp 并下载官方多语言 small 模型，或者配置已有模型路径。详见[本地识别安装](local-asr.md)。示例项目设置：

0.6.5 的自动同步检查还需运行 `bash scripts/install-subtitle-alignment.sh`，安装另一套本地中文 CTC 声学模型及隔离运行环境。默认针对普通话；外语、重叠对白和无法独立识别的声音不会被当作已经验证。`nolan doctor` 可检查是否就绪。不需要新增 API Key。

```json
{"postproduction":{"enabled":true},"subtitles":{"mode":"local","backend":"whisper_cpp","language":"zh","call_cap":0}}
```

字幕源是实际识别文字，计划对白只作为当前集的短参考。GPT 不接收小说、历次报告或全部提示词，不新增未识别的对白，不推测数字；GPT 的文字校对步骤保持本地识别结果的时间和数量不变。每批最多60条，已完成校对按输入哈希缓存，重启后复用。原声音轨、模型或本地对齐策略改变则重新本地识别。识别结果为空而本集计划有对白时会停止，不伪装成已完成字幕。

本地识别仍可能误听数字、人名和叠音；文字校对不代表 GPT 听过音频。字幕文字准备后先自动检查与实际人声的同步，有疑点则在本机重新对齐，再复检，单次后期请求最多修复两轮。自动检查通过后才开放带字幕配乐整集的最终人工批准。

### 字幕同步自动检查与最终验收

“本集后期 → 字幕”提供默认折叠的同步检查报告，显示检查状态、已检查字幕数、本轮修复次数，以及仍有疑点的时间区间和原因。检查中、重新对齐中和仍有疑点是不同状态，不能用“GPT 已校对文字”代替时间检查。

同步结果与当前原声音轨、字幕内容和源视频版本绑定；修改字幕、音轨或来源后不能继续使用旧检查的通过记录。旧版成片没有自动检查记录时，仍可预览同一当前导出文件，但不能直接完成新的最终批准。已有人工批准记录保留，不因升级自动撤销。

两轮后仍无法验证的结果明确停在“字幕同步需要处理”，不伪装通过。“查看字幕检查报告”只定位到报告，不再次启动处理；可在原“修改字幕”框内补充问题或修正意见，发起一次明确的新请求。检查和时间修复只在本机处理字幕，不重新生成视频、声音或音乐；原片段、累计拼接预览和审批进度保留。

自动检查只覆盖当前可核验的范围，不是精确逐字听审的保证。通过后仍须完整播放最终成片，由用户验证字幕、实际声音和画面，并决定批准或提出意见。

### 手动微调后只合成，不再自动复检

字幕表的文字、开始和结束秒数可以直接编辑。点“确认调整并试看”明确采用这组人工设置，只在本地合成新版，不再调用识别、GPT 或同步检查，也不会自动改回你输入的时间。页面标注“手动调整版”，保留此前机检报告为历史，不能将此版本称作机器检查通过。人工采用记录与当前音轨、字幕、源片和导出版本绑定；你播放新版后仍需最终批准。只改配乐也会复用已有字幕，不触发字幕复检。

自动字幕候选优先从对应分镜的剧本台词提取，再由实际音频核对起止和内容；识别有明确差异的数字不会凭剧本覆盖，没有说出的剧本句子不会直接补上。

### 在同一个反馈框修正文字与时间

在本集后期的“修改字幕”中既可以反馈错字，也可以反馈“前五条出现太早”“字幕比声音晚”“重新对齐”。不需要另选流程，也不要求用户逐条提供秒数。本集后期的每次字幕返修都从当前原声音轨的本地识别与对齐结果重新建立字幕，再按反馈校对文字；不会直接沿用旧成片的字幕时间戳作为返修基础。对齐策略或音轨已改变时会重新识别；相同音轨和对齐策略已经完成的本地结果可以复用。

终端也可以明确输入 `E001 请重新对齐字幕，前五条出现太早`，走同一字幕返修入口；查询、假设、否定及仅描述问题不会自行开始返修。

用户指出的条目和时间点作为检查线索完整保留，最终时刻仍以实际音频为依据。GPT 只负责字词校对，不能根据剧本、字数或“顺延几秒”的文字推测新时间，也不能声称文字校对等于已经听审、已修好同步。较早已明确修正的字词仅作为参考，不能把没有实际说出的剧本对白补进字幕。

字幕返修保留所有视频片段、片段审批及已有音乐编排，只重新生成字幕与本集最终合成版本；不会为了字幕错误重新付费生成视频或人声。新成片会显示在“最终成片预览”并重新等待用户审批，旧成片和字幕保留。自动对齐仍可能有误，不能把结构有效或本地处理完成视为准确性保证。

## 兼容的云端模式

Nolan 的自动字幕从已经生成的视频音轨识别文字和时间，不把剧本台词直接当成实际对白。分镜阶段仍然规划台词；当前主流程先将本集镜头合成，再识别整集实际音轨，时间戳直接对应本集时间轴。镜头重生成或时长变化后，应重新识别合成音轨并重建字幕。

旧项目可选的云端适配器使用 OpenAI `POST /v1/audio/transcriptions`，选择 `whisper-1`、`verbose_json` 和分段时间戳。该组合已经依据官方文档核实；当前代码不接受直接替换为没有相同时间戳返回约定的模型。[OpenAI 转录接口](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)、[文件转录指南](https://developers.openai.com/api/docs/guides/speech-to-text)

配置放在项目的 `settings.subtitles` 中：

```json
{
  "mode": "openai",
  "model": "whisper-1",
  "api_key_env": "OPENAI_API_KEY",
  "call_cap": 0,
  "timeout": 120,
  "language": "zh"
}
```

`language` 可以省略以使用自动识别。`call_cap` 是每集转录一次的保守费用上限，使用项目账本币种；示例的 0 必须按实际服务价格和本集长度改成足够的正数，再批准总预算。API 密钥通过环境变量提供，不写入项目配置。请求固定发送到官方 OpenAI 地址，不跟随重定向；ChatGPT/Codex 登录本身不为这个 HTTP 接口提供 API 密钥。

底层接口为 `Transcriber(config).transcribe(audio_path)`，返回 `[{"start": 0.2, "end": 2.1, "text": "实际识别文字"}]`，时间单位为秒，相对于输入音轨起点。接口可以接受单镜或整集音轨，当前主流程每集调用一次。单次文件上限为 25 MB，超过上限会停止，不会默默截断音频；需要先压缩或另行实现分块及时间偏移。无须为此购买另外的配音服务。[文件大小与时间戳说明](https://developers.openai.com/api/docs/guides/speech-to-text)

转录前检查真实音轨与时长，转录后拒绝倒序、明显重叠、负时间、超出音轨和没有时间戳的非空文本。最多 50 毫秒的边界误差按实际长度收齐。未识别出对白时返回空字幕；不会用预先写好的对白补足。超时、断网或无效返回可能发生在计费之后，因此抛出 `ProviderError(uncertain=True)`，交由账本保留待核实费用，绝不自动重发付费 POST。

这些检查只说明时间结构合理，不能证明识别准确。背景音乐、低音量、多人重叠、专有名字和生成语音异常仍会导致漏字、错字或幻觉。ASR 结果是待核对字幕；最终每集审批要同时检查字幕、实际声音及口型。抽帧视觉检查也不能代替试听。

已有字幕的成片可单独校正字幕。例如在终端对话中输入 `E001 字幕 把“你好”改成“您好”`，或者运行 `nolan captions 项目目录 E001 --version 1 --correction '把你好改成您好'`。校正针对所见的具体版本，再重新合成供人工审片；启用本集后期的项目采用上述本地重新识别与对齐流程。未启用本集后期的兼容旧流程只校正文字、保留旧时间戳，不提供时间修复能力。网页审片室也有独立的“修改字幕”按钮。对白本身错误、漏说或口型错误应通过镜头返工处理。

没有配置转录时可以选择主流程提供的无字幕或人工对齐方式，但不能将计划台词标成“已与实际声音校准”。云端适配器没有进行付费测试。本地识别路径已在 Apple Silicon Mac 上用已有视频音轨验证。
